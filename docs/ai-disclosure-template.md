# AI disclosure

Every PR includes an AI-disclosure block so reviewers know what kind of review
to apply. The block is part of the Definition of Done and is generated by
`.claude/skills/create-pr.md`.

## Template

```markdown
## AI disclosure

- **Tool:** Claude Code (model: <claude-opus-4-7 | claude-sonnet-4-6 | claude-haiku-4-5>)
- **% AI-generated:** <estimate, e.g. ~70%>
- **Human review applied:** <what the human author read, ran, and verified>
- **Agents invoked:** <security-reviewer, none, etc. — include one-line finding>
```

## How to estimate % AI-generated

This is an honest estimate, not a precise metric. Pick the bucket:

| Bucket | When |
|---|---|
| `<20%` | Agent made small edits to human-written code; human wrote the bulk. |
| `~50%` | Pair-authored: human outlined, agent filled in, human refactored. |
| `~70%` | Agent wrote most of it following a human-written spec. |
| `~90%` | Agent authored end-to-end from a short prompt; human reviewed. |
| `100%` | **Never use.** A human reviewed it, so at minimum that counts as input. |

## What "human review applied" should contain

Concrete actions, not platitudes. Bad: "reviewed the code". Good:

- "Read every file in the diff line-by-line."
- "Ran `npm test` and `npx playwright test` locally; both green."
- "Manually tested the guest flow on the Vercel preview URL."
- "Verified the `security-reviewer` output and opened a follow-up issue for
  the one Concern it flagged."

## Why we do this

A reviewer's job changes based on provenance:

- **Mostly human:** conventional review — does the logic make sense, is it
  maintainable.
- **Mostly AI:** additional suspicion — does every file in the diff need to
  exist, are the tests meaningful or tautological, did the agent invent an
  API that doesn't exist.

Without disclosure, the reviewer applies the wrong kind of attention and
either over- or under-checks the diff.
